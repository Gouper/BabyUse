## 已发现并回归修复

初版邀请token向普通成员泄露、失败操作部分写入、请求重试重复扣、过期未开封罐不能报损、初始单罐开封影响同批未开封罐、结束容器后盘点重复扣、默认开罐未按最早到期排序，均已由后端修复并加入回归测试。UI更正动作API、批次remaining来源以及全部WXML条件/循环动态绑定已修复，并增加静态回归检查。

## 未验证与限制

- 云适配模拟测试覆盖身份、重试、移除成员和通知成功/失败/未配置，模拟器不等于真实腾讯云事务。没有可用环境 ID、数据库实例、模板 ID 或微信登录授权证据；本地未运行微信编译/真机，未证明双成员云并发与真实订阅投递。
- 家庭库存、全部流水、幂等键及通知历史保存为单家庭文档，随长期使用增长。需在投产前核对云数据库文档大小并制定归档/拆分策略。
- 微信外部投递与数据库状态提交不能成为同一事务；进程在发送前后崩溃可能留下 sending 状态。当前需人工查投递记录，不能盲目重发。
- 跨盘点区间总量无法推断盘点前后真实使用比例，明确要求拆分记录；不伪造分配。
- 复杂补记/盘点下客户端趋势累加与领域库存回放一致性尚需额外集成测试；不要将图表当作实际可用余量。

结论：本地业务与页面契约检查通过，尚未完成真实云环境和微信首版验收。

## 2026-11-19 使用流程简化

首页、记录页与用品行均直接打开使用表单，页内选用品、填写带单位的用量与日期；开封类用品在同页选择开始使用或用完。库存明细默认折叠，日常使用不要求选择批次，沿用服务端自动分配。

独立验证通过 42 项本地测试、6 个 JavaScript 语法检查与 8 个 WXML 原生 wcc 离线编译。新增行为测试覆盖空数量拦截、用品筛选、容器操作、加载失败、隐藏区间日期清理和成功后防重复提交。未进行微信真机或真实云端库存操作验证。

## 2026-11-19 添加用品字段错误修复

复现奶粉预设未填写开封天数时保存，原服务端返回“数量必须为有效正数”，实际并非缺少库存数量。现前端校验名称、计数单位、每包数量、开封天数与提醒设置，并在对应字段下显示错误。开封天数按包装填写，未设置默认天数。服务端对每包数量、开封天数返回具体字段错误。添加用品页明确说明此处只建资料，实际库存数量在入库时填写。

新增前后端回归先确认 4 项失败，修复后 46 项本地测试全部通过；修改的 2 个 JavaScript 文件语法检查及 editor.wxml 原生 wcc 离线编译通过。未进行真实云端部署及微信真机验收，服务端错误文案修复需重新部署 api 云函数。
