## 0. 项目背景与接手说明

### 0.1 我们要编写什么

开发一个运行在微信中的宝宝用品管理小程序。家庭成员通过自己的微信身份加入同一个家庭，共享一个宝宝的用品库存、使用记录和提醒。主要在手机上完成操作，不依赖电脑或 Excel。

产品定位是家庭日常库存与有效期管理工具，首版不包含商城、支付或商品销售，也不承担完整的育儿健康记录功能。AD 等用品的登记属于库存管理，不延伸到医疗判断。

用户打开小程序应能快速回答四个问题：

1. 家里现在有哪些用品，各剩多少？
2. 哪些快用完，需要提前购买？
3. 哪些即将过期或超过开封期限，需要优先使用或处理？
4. 家人最近购买、使用或调整过什么，库存变化是否有据可查？

### 0.2 真实使用背景

用户目前用纸质本子记录宝宝每天的使用量，例如尿不湿每天用了多少片。记录会偶尔漏记，纸质记录不能自动更新库存，因此有时不清楚家中余量，也不容易发现物品即将过期。

用户希望将记录和库存管理结合起来，让家庭成员共同维护，减少重复购买、临时缺货和过期浪费。优先解决存量、补货和有效期问题，趋势图用于了解实际消耗并辅助判断何时补货。

第一版由成员在小程序中手动录入。纸质本子中的历史记录不会自动同步；拍照扫描本子、图片识别录入属于后续方向，本次不实现。

### 0.3 使用者与日常习惯

- 主要使用者是宝宝的父母及受邀家庭照顾者，以手机操作为主。
- 第一版每个家庭管理一个宝宝，家庭库存共享，不为每个成员单独建一份库存。
- 消耗频繁且数量可数的用品，例如尿不湿、AD，按天记录实际使用数量，允许补记。
- 奶粉采用开罐／用完记录，避免要求每日称量；抚触油建议沿用开瓶／用完方式。
- 家庭会漏记，所以账面余量不能被描述为保证准确的实物数量，估算也需要说明依据不足的情况。
- 用户希望在微信中主动收到通知，并在进入小程序和查看余量时持续看到提醒。

### 0.5 典型使用流程

**首次整理家庭库存**

创建家庭 → 邀请成员 → 添加或选择物品 → 选择使用方式及有效期规则 → 通过“整理现有物品”连续添加或粘贴文字 → 检查数量、包装换算、批次及已开封状态 → 确认保存。

**日常记录与采购**

查看首页待处理事项 → 登记当天尿不湿／AD 的实际用量，或记录奶粉开罐／用完 → 库存和估算随记录更新 → 需要购买时查看待补货用品 → 买回后通过“新购入库”登记。采购清单、下单或购物平台联动不是本流程所要求的功能。

**有效期处理**

查看临期提醒 → 定位具体批次或开封容器 → 优先使用 → 已过期则保留在待处理清单，排除出可用余量 → 实际丢弃后登记报损并留下记录。

**漏记后恢复准确性**

发现账面可能偏高 → 可以补记实际用量，或清点后使用“盘点校准” → 系统保留校准时间和差额 → 以后补记校准前的历史用量时避免再次扣减当前库存。

## 1. 目标与范围

帮助家庭了解宝宝用品的存量、需要补充的用品以及需要优先使用的用品。通过每日使用记录、开封记录和批次有效期，提供低库存、预计用完及临期提醒。

第一版一个家庭管理一个宝宝，支持多个微信成员共享数据。保留未来扩展空间，但不实现多宝宝管理。

## 2. 家庭与权限

数据归家庭所有，不同家庭之间必须隔离。创建家庭者默认是管理员，使用中的家庭至少保留一位管理员。

| 操作 | 管理员 | 普通成员 |
| --- | --- | --- |
| 查看库存、趋势、历史 | 可以 | 可以 |
| 添加自定义物品、批量录入、购买入库、记录使用 | 可以 | 可以 |
| 修改、撤销使用记录 | 全部记录 | 自己的记录 |
| 盘点校准、登记报损 | 可以，填写原因 | 可以，填写原因 |
| 批量删除、恢复物品 | 可以 | 不可以 |
| 邀请、移除成员、设置角色 | 可以 | 不可以 |
| 微信提醒 | 自行订阅 | 自行订阅 |

邀请通过微信分享入口完成，对方确认后加入；邀请应支持失效和撤销。成员退出或被移除后，失去访问权限，历史操作归属仍保留。具体邀请有效时长属于实现细节，尚未指定。

最后一位成员可以确认退出并关闭家庭，现有邀请随即失效。自退出起 72 小时内，原微信账号可以在家庭页找回家庭，恢复管理员身份、库存和历史记录。已有家庭时需先退出当前家庭。超过期限后无法找回，到期数据由云端定时任务清理。

## 3. 自定义物品与管理类型

支持添加任意自定义物品，自定义分类和计量单位。分类用于查找，管理方式决定库存、使用和提醒规则，两者相互独立。

### 3.1 两个独立设置

**使用记录方式**

1. 按数量消耗，例如片、粒、个，每日记录实际使用量。
2. 按开封／用完，例如罐、瓶，记录每个容器的开封和结束使用时间。

**有效期管理**

1. 不管理有效期。
2. 只管理包装有效期。
3. 同时管理包装有效期和开封后期限。

使用记录方式与有效期设置可以自由组合，不根据物品名称强制绑定。

### 3.2 快捷类型

| 示例 | 使用方式 | 有效期默认规则 |
| --- | --- | --- |
| 尿不湿 | 按片消耗，购买按包换算 | 不管理有效期，不参与临期提醒 |
| 奶粉 | 按罐记录开罐／用完 | 包装有效期和开封后期限 |
| AD | 按粒消耗，购买按盒换算 | 管理包装有效期 |
| 抚触油 | 建议按瓶记录开瓶／用完 | 可设置包装有效期和开封后期限 |

以上为初始配置建议，用户添加时可以修改。开封后期限依据用户提供的包装信息填写，不统一写死。AD 仅记录库存与实际使用，不提供剂量建议。

物品信息应能表达名称、分类、规格、基本单位、包装换算、使用方式、有效期规则和提醒阈值。同款不同规格需要明确区分，导入时不能仅凭名称自动合并。

## 4. 库存与批次

同一物品可以存在多个批次，各自记录数量、有效期及来源。需要管理有效期时，使用默认优先扣除最早到期的可用批次，并允许手动选择。

按数量管理的用品，购买包装换算为基本单位，例如两包、每包 50 片，增加 100 片。保存本次换算信息，后续修改包装规格不得改变历史入库数量。

按开封管理的用品分别展示未开封数量和使用中数量。开罐／开瓶只转移状态，不作为整罐正常消耗；用完才结束该容器的使用记录。支持多个容器同时使用，不把正在使用的半罐当作完整未开封库存。

同时存在包装和开封期限时，按较早日期判断到期。过期用品排除出可用余量，但保留在待处理清单，直到成员确认报损；过期标记本身不能与报损重复扣减。

## 5. 手机批量录入

提供两个明确入口，两者都支持连续添加和粘贴文字解析。

| 入口 | 用途 | 统计处理 |
| --- | --- | --- |
| 整理现有物品 | 初始化现有库存或补录此前未登记的用品 | 增加库存，标记期初／补录，不计入新购统计 |
| 新购入库 | 登记新购买的用品 | 增加库存，计入采购入库趋势 |

整理现有物品支持录入已开封容器和开封日期。账实不符应使用盘点校准，不能通过反复初始化增加库存。

### 5.1 连续添加

连续填写多个物品后统一预览、确认保存。同款可沿用规格，快速增加不同批次。

### 5.2 粘贴文字

示例输入：

```text
纸尿裤L码 2包 每包50片
奶粉900克 3罐 有效期2027-08-01
AD 2盒 每盒30粒
抚触油100毫升 1瓶
```

解析出物品、规格、数量、单位、日期，并提供逐项修改。缺失换算信息、匹配不确定或日期含义不明确时标记待确认，不静默猜测。需要有效期但暂未填写的物品允许保存，明确显示无法提供完整临期提醒。

批量录入必须先预览再确认。保留批次操作记录，防止同一次提交因重复点击或请求重试重复入库；再次导入相同文本时提示潜在重复，由用户核对，不能阻止真实的重复采购。

第一版不支持 Excel 模板导入，不实现图片识别。

## 6. 使用记录、漏记与校准

### 6.1 按数量登记

支持按日期一次填写当天使用数量，也支持补记历史日期、一次补记几天的总用量。记录操作人、发生日期和录入时间。

默认按家庭存在漏记的情况设计。没有记录不等于没有使用，漏记日期不能按零消耗统计，也不自动猜测并扣库存。页面明确区分账面余量与实际余量可能存在的偏差。

### 6.2 开封／用完

奶粉记录购买、开罐、用完；抚触油采用相同方式作为默认建议。中途丢弃使用报损结束，不能计为正常用完，避免污染正常使用时长统计。

### 6.3 盘点与修改

支持输入实数校准库存，记录调整前后数量、原因、操作人和时间。盘点差额单独归类，不能算入正常消耗。

盘点后补记盘点之前的用量，不得再次扣减已经包含该消耗的盘点后余量。补记、撤销、修改和盘点均需定义明确的生效时间与关联关系；实现时必须覆盖同日先后顺序和跨日补记场景。

几天总用量可参与区间平均估算，但不能假装拥有每天的精确明细；趋势图需要标注为区间汇总。

## 7. 余量估算与提醒

### 7.1 预计用完

按数量用品展示账面可用余量、近期日均用量、预计可用天数和预计用完日期。建议默认使用最近七天中有效的日用量记录；漏记不作为零，记录不完整时标明估算偏差并建议核对库存。

按开封用品根据正常用完容器的历史使用时长估算，结合当前开封时间和未开封数量计算，不能将已开封容器按完整一罐计算。没有足够历史时显示“数据不足，暂无法估算”，不生成虚假精确日期。

过期库存不计入可用余量。估算结果随实际记录和校准更新，不自动改变库存账目。最低样本数、异常值处理及连续漏记提示阈值尚未指定，应在实现设计中明确。

### 7.2 提醒规则

| 类别 | 默认触发条件 |
| --- | --- |
| 低库存 | 低于物品自行设置的数量阈值 |
| 快用完 | 预计可用时间不足 7 天 |
| 临期 | 有效期提前 30 天 |
| 开封期限 | 到期前 3 天 |
| 已过期 | 已超过适用期限，进入待处理 |

每种用品可独立调整规则。不管理有效期的物品不触发临期提醒，仍支持低库存和预计用完提醒。

### 7.3 小程序内提醒

进入首页即可看到库存不足、快用完、临期和过期待处理的数量与入口，不依赖微信通知是否成功。提醒持续展示到问题解决，不要求每次进入强制弹窗。点击进入相关物品或批次，方便补货、优先使用或报损。

### 7.4 微信主动通知

默认每天北京时间上午 9 点检查待提醒事项，存在符合条件的事项且具备发送权限时通知。低库存也应随使用记录及时更新应用内状态。

每个成员自行订阅，可选择接收提醒。相同批次、相同提醒级别避免重复通知，紧急程度升级可再次提醒；具体合并、升级及再次提醒间隔需在实现设计中确定。

微信一次性订阅需要用户主动授权，不能承诺一次开启后永久每日推送。拟在每日记录完成后提供主动订阅入口；可用消息模板和长期订阅资格需核实实际小程序后台。缺少授权或发送失败时，保留应用内提醒及发送状态，不伪装为通知成功。

能力参考：[腾讯云小程序订阅消息官方说明](https://cloud.tencent.cn/document/product/1301/103770)，于 2026-11-19 查阅。

## 8. 报损、删除与历史

报损适用于过期、洒漏、丢失、剩余丢弃等，所有成员可登记，必须保留原因及受影响批次。与正常使用分开统计。

管理员可批量删除物品，进入回收站并支持恢复。删除是停止展示／管理，不等于消耗或报损，不能抹掉历史流水或被计入正常消耗趋势。回收站中的物品不参与日常补货提醒。

相关操作至少保存家庭、物品／批次、操作类型、数量变化、操作者、业务发生时间、实际记录时间、原因及批量操作关联。更正通过关联记录追溯，不能覆盖掉原始历史。

## 9. 趋势分析

第一版必须提供库存变化、正常消耗和采购入库趋势，支持按物品和日期查看。期初／补录、采购、正常使用、报损和盘点调整分别归类。

漏记不补造零消耗数据，区间补记标明区间；不同基本单位不能直接相加为“总库存数量”。按开封用品展示正常用完数量和使用时长，不能虚构每日克数／毫升数。

采购支出分析暂不作为首版必需项；未来启用时，缺少价格的记录应注明统计不完整。

以下为待整体确认的组织方案，不代表已确认视觉设计：

- 首页：待补货、快用完、临期、过期待处理，趋势入口。

## 11. 技术边界与实施前确认项

现有目录是微信原生小程序初始骨架，未实现业务。讨论中的技术方向为原生小程序结合云端数据和服务；云环境、数据库类型、实际消息模板及部署配置尚未核实，不作为既定事实。

家庭访问权限必须由服务端验证，库存变化与流水写入需要保持一致，并处理多成员并发和重复请求。不得仅依赖客户端隐藏按钮实现权限控制。

实现前应明确但无需重新讨论已确认需求的事项：

- 云环境与数据库能力、通知模板可用性。
- 估算样本标准、区间补记和校准的计算规则。
- 邀请有效期、通知去重及升级间隔。
- 管理方式或基本单位变更对已有库存的迁移限制。

这些属于后续技术设计和验证工作，本次只产出需求 Spec。

## 12. 首版验收场景

1. 添加自定义物品，可分别选择消耗方式和有效期规则；尿不湿默认不要求有效期，AD 可同时按粒使用和管理有效期。
2. 两位家庭成员共享库存，普通成员无法绕过服务端权限执行批量删除或成员管理。
3. 连续添加和粘贴文字均经过预览；两包每包 50 片正确增加 100 片；不明确的信息要求确认。
4. 整理现有物品与新购入库分别进入正确统计，重复请求不重复增加库存。
5. 不同有效期批次可分别追踪，默认优先使用最早到期的可用批次。
6. 每日使用、漏记补录、区间补记、盘点、撤销组合后库存保持一致，盘点前的历史补记不重复扣减当前余量。
7. 奶粉开罐后转为使用中，用完后保留使用时长；中途丢弃不计入正常喝完样本。
8. 首页显示低库存、快用完、临期、已过期事项；余量估算在缺少记录时明确说明不确定性。
9. 微信通知在具备有效授权与模板时可发送并跳转查看，无权限或发送失败时应用内提醒继续存在。
10. 报损、批量删除及恢复保留历史，过期批次排除出可用库存且不重复扣减。
11. 趋势区分采购、期初、消耗、报损及校准，不将漏记日期伪装为零消耗。

## 13. 不在第一版范围

- Excel 模板导入。
- 图片扫描、拍照识别记账，后期考虑。
- 多宝宝管理。
- 医疗建议或 AD 剂量指导。
- 缺少历史依据时生成精确消耗预测。
- 尚未核实平台资格时承诺无限、持续的微信推送。
